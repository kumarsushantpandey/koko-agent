## 1. Executive Summary & System Architecture

The **Akari Watanabe AI Companion** (`AiAkari`) is a low-latency, multimodal AI assistant application featuring an interactive 3D anime avatar rendered in real time in the browser via WebGL/Three.js, driven by an asynchronous Python backend.

### 1.1 Core Subsystems
- **3D VRM Anime Avatar Engine**: 60 FPS WebGL rendering with Three.js, React Three Fiber, procedural eye blinking, breathing motion, camera tracking, and a rich library of `.vrma` and `.bvh` animations.
- **Multi-Character Companion Support**: Hot-swappable companion registry supporting **Akari Watanabe** (tsundere gyaru companion) and **Espeon** (psychic companion) with zero page reloads and WebGL resource disposal.
- **Pluggable Foundation Model Providers**: Dynamic runtime switching across 5 LLM inference gateways:
  1. **AWS Bedrock Mantle** (OpenAI-compatible distributed inference via bearer token or AWS credentials).
  2. **OpenAI** (GPT-4o, GPT-4o Mini, GPT-4 Turbo).
  3. **Mistral AI** (Ministral 8B, Pixtral 12B native vision, Mistral Small).
  4. **OpenRouter Free Tier** (Auto-router, Google Gemma 4 native tool calling, Ling 3.0 Flash, Liquid LFM, Space Bunny, Qwen 3.8).
  5. **Free.ai** (Qwen 2.5 7B, Qwen 3 8B).
- **20-Round Agentic Tool Execution**: 12 registered built-in tools covering dynamic tool discovery (`get_available_tools` / `get_tool_list`), real-time clock and worldwide timezones, calendar calculations, exact math expressions, OS runtime health, and multi-tier live web search/crawling.
- **Audio-Synchronized Emotion & Lip Sync**: Dual-layer synchronization binding VRM facial blendshapes (`Happy`, `Sad`, `Angry`, `Surprised`, `Relaxed`, `Neutral`) to audio playback segments, and audio-reactive FFT frequency analysis for mouth visemes (`aa`, `ih`, `ou`, `ee`, `oh`).
- **Hybrid Multimodal Vision**: Offscreen canvas downscaler (1280x1280 JPEG 0.85) supporting camera capture, drag-and-drop, and clipboard paste (`Ctrl+V`), with automatic visual extraction fallback for text-only foundation models.
- **Summary Buffer Memory Compaction**: Automatic background summarization that compresses dialogues exceeding 16 messages or 8,000 characters while preserving recent context verbatim.
- **Full-Duplex WebSocket Bridge**: Single persistent TCP socket supporting bi-directional streaming: 16kHz PCM audio streaming for Whisper transcription and typed JSON event broadcasting.

## 3. Multi-Character 3D VRM & Animation Pipeline

The 3D rendering pipeline is encapsulated inside `./client/src/components/character/` using `@pixiv/three-vrm` and `@react-three/fiber`.

### 3.1 Character Registry & Extensibility (`./client/src/components/character/types.ts`)
The avatar registry allows declaring arbitrary VRM humanoid models with individualized metadata:

```typescript
export interface CharacterDefinition {
  id: string;
  name: string;
  displayName: string;
  subtitle: string;
  categoryTag: string;
  tagNumber: string;
  role: string;
  description: string;
  vrmUrl: string;
  avatarUrl: string;
  voiceEngine: "fish" | "sovits";
  placeholderText: string;
  position?: [number, number, number];
  scale?: number;
}
```

Active companions:
1. **Akari Watanabe (`akari`)**:
   - Model asset: `./client/public/characters/default.vrm`
   - Height: 1.65m, scale: 1.0, position: `[0, 0, 0]`
   - Persona: Gyaru tsundere from *More Than a Married Couple, But Not Lovers*.
2. **Espeon (`espeon`)**:
   - Model asset: `./client/public/characters/Espeon.vrm`
   - Height: 1.78m, scale: 0.9, position: `[0, 0.07, -0.10]`
   - Persona: Psychic Pokémon companion, perceptive, elegant, protective.

### 3.2 Dynamic Hot-Swapping & Memory Disposal (`./client/src/components/character/Character.tsx`)
When switching characters via the Overview screen or URL (`?character=espeon`):
1. Previous animation mixer actions are stopped: `mixer.stopAllAction()`, `mixer.uncacheRoot(vrm.scene)`.
2. VRM scene graph is traversed, disposing of all `geometry` instances and `materials` (including material arrays).
3. Active subscriptions to the WebSocket event bus in `LipSyncController` and `EmotionController` are cleanly terminated.
4. The React state unmounts the old primitive and `loadAvatar()` asynchronously loads and binds the new VRM scene.

### 3.3 Humanoid Bone Resilience (`./client/src/components/character/DefaultPoseController.ts`)
Both characters share standard 54-bone humanoid hierarchies. To prevent runtime null-pointer exceptions when models possess slight skeletal deviations, all bone retrievals utilize defensive optional chaining:
```typescript
const leftUpperArm = vrm.humanoid?.getNormalizedBoneNode("leftUpperArm");
```

### 3.4 Procedural Controllers
- **`BlinkController.ts`**: Natural human blinking driven by procedural timers with randomized 2–6 second intervals, applying blendshape morph target weights to `blink`.
- **`BreathingController.ts`**: Subtle, continuous chest and spine translation driven by a smooth sine wave (`Math.sin(time * 1.5)`), creating the illusion of breathing.
- **`LookAtController.ts`**: Real-time head and eye tracking that follows the camera position in 3D space with damping.
- **`LipSyncController.ts`**: Audio-reactive lip-sync reading live frequency data from the Web Audio `AnalyserNode`. Converts RMS amplitude to blendshape weights across `aa`, `ih`, `ou`, `ee`, and `oh`.
- **`EmotionController.ts`**: Lerps between 6 facial expression presets (`Happy`, `Sad`, `Angry`, `Surprised`, `Relaxed`, `Neutral`). Crucially avoids touching mouth visemes so lip-sync is never overridden.

### 3.5 Windows Vite File Watcher Stabilization
Large `.vrm` files (20MB+) placed in `./client/public/` caused Node `fs.watch` to throw `UVException EBUSY: resource busy or locked`. This is eliminated in `./client/vite.config.ts`:
```typescript
server: {
  watch: {
    ignored: ['**/*.vrm', '**/characters/**', '**/public/characters/**'],
  },
}
```

### 4.2 Amazon Bedrock Mantle Integration (`./server/src/llm/bedrock_model.py`)
- **Bearer Token Auth**: Uses `AWS_BEARER_TOKEN_BEDROCK` (`Authorization: Bearer <key>`) with the OpenAI Python SDK pointing to `https://bedrock-mantle.{region}.api.aws/v1`.
- **Region Inference**: Parses the region from `BEDROCK_REGION`, `AWS_REGION`, or extracts it from the decoded bearer token credential string (default: `ap-south-1`).
- **Gemma 3 vs. Gemma 4**:
  - Bedrock Mantle hosts Gemma 3 models which drop tokens when function tools are passed alongside system prompts; `bedrock_model.py` automatically routes Gemma 3 via conversational streaming bypass.
  - OpenRouter natively hosts Gemma 4 (`google/gemma-4-31b-it:free`), which supports function calling via `<|tool_call|>call:name{args}<|tool_call|>` delimiter parsing.
- **Modality Boundary & History Sanitization**:
  Past turns with images are converted to plain text descriptors in conversation history (`[Image attached] {user_text}`). This prevents Bedrock Mantle from rejecting subsequent turns with HTTP 400 (`Model does not support image modality`) when switching between vision and text-only models.
- **Windows Console UTF-8 Reconfiguration**:
  Emoji generation on Windows cmd/PowerShell previously threw `UnicodeEncodeError: 'charmap' codec can't encode character`. Fixed in `./server/src/main.py`:
  ```python
  if sys.platform == "win32":
      sys.stdout.reconfigure(encoding="utf-8", errors="replace")
  ```

## 5. Tool Calling & Agentic Execution Subsystem

The tool calling subsystem enables Akari to execute functions to obtain live real-world information.

### 5.1 Tool Catalog & Registry (`./server/src/tools/`)

| Tool Name | Aliases | Description |
|---|---|---|
| `get_available_tools` | `get_tool_list`, `tool_list`, `list_tools` | **Mandatory Pre-Decline Discovery**: Returns all active registered tools and schemas. |
| `get_current_time` | `time`, `clock` | Time and date for user's local timezone or any city/timezone worldwide. |
| `get_timezone_info` | `timezone_info` | Detailed IANA timezone identifiers and UTC offsets (e.g. UTC+05:30). |
| `convert_time` | `time_convert` | Converts specific times between two timezones/cities with day offsets. |
| `time_difference` | `time_diff` | Calculates exact time difference and compares time across two locations. |
| `get_current_date` | `date`, `today` | Full calendar date, day of week, month, year, and day of year. |
| `get_day_of_week` | `day_of_week` | Day of week for past, future, or relative dates (e.g. 'tomorrow'). |
| `calculate` | `calc`, `math` | AST-safe precision mathematical expression evaluator. |
| `get_system_status`| `system_status` | Runtime health telemetry: host OS, Python version, model, WebSocket status. |
| `web_search` | `search`, `google` | Multi-tier live web search (Tavily AI $\to$ DuckDuckGo fallback). |
| `fetch_web_page` | `read_url`, `web_fetch` | URL content extractor (Tavily Extract API $\to$ direct HTTP GET fallback). |

### 5.2 Mandatory Pre-Decline Rule & Discovery Enforcement
To eliminate false declines (*"I don't have a tool to check system status"*):
1. **Registered Alias**: `get_tool_list` is explicitly registered alongside `get_available_tools`.
2. **Resilient Registry Lookup**: `ToolRegistry.get_tool(name)` resolves common model hallucinations (`get_tool_list`, `tool_list`, `list_tools`, `get_tools`).
3. **Prompt Directive**: `./server/src/prompts/system_prompt_akari.py` strictly mandates:
   > *"BEFORE declining any user request, saying you cannot do something, claiming you lack capability, or declining a tool call: YOU MUST FIRST EXECUTE `get_available_tools` (or `get_tool_list`) to check your active registered tools catalog!"*

### 5.3 20-Round Execution Window Scaling
Multi-step agentic workflows require chaining tools across turns. The tool loop limit is scaled to 20 rounds:
- Config: `MAX_TOOL_CALL_ROUNDS = int(os.getenv("MAX_TOOL_CALL_ROUNDS", "20"))`
- Server streaming loops: `bedrock_model.py`, `openai_model.py`, `mistral_model.py`, `openrouter_model.py`, and `chat/loop.py` enforce `max_tool_rounds = 20`.
- WebSocket bridge: Clamping relaxed from `min(10, ...)` to `min(20, ...)`.
- Client networking: `AvatarSocket.ts` defaults `maxCalls` to `20`.

### 5.4 Conversational Stalling Prevention & Heuristic Retries
Small models (e.g. 8B parameters) often generate conversational promises (*"[angry] Wait a sec, I'll check!"*) instead of emitting structured tool calls.
1. `_has_explicit_tool_intent(prompt)` detects URLs, calculation expressions, or tool keywords.
2. If tool intent is detected, `tool_choice="any"` compels the model to invoke a tool.
3. If the model emits stalling phrases without calling a tool, the response is intercepted, withheld from the user, and re-executed with forced tool choice.

## 6. Audio-Synchronized Emotion & Lip-Sync Subsystem

The emotion synchronization engine guarantees that 3D VRM facial expressions shift in **exact lockstep** with spoken audio.

```
+-----------------------------------------------------------------------------------------+
| LLM Response: "[happy] Look what I found! [angry] But don't expect me to do it again!"  |
+-----------------------------------------------------------------------------------------+
                                             │
                                             ▼
                 split_dialogue_units_with_emotions() (emotion_feature.py)
                                             │
         ┌───────────────────────────────────┴───────────────────────────────────┐
         ▼                                                                       ▼
Segment 0:                                                              Segment 1:
- Text: "Look what I found!"                                            - Text: "But don't expect me to do it again!"
- Emotion: "Happy"                                                      - Emotion: "Angry"
- TTS: Synthesized WAV Data URI                                         - TTS: Synthesized WAV Data URI
         │                                                                       │
         └───────────────────────────────────┬───────────────────────────────────┘
                                             ▼
                                  WebSocket speech_segment Events
                                             │
                                             ▼
                     client/src/audio/SpeechQueue.ts (Sequential Playback)
                                             │
         ┌───────────────────────────────────┴───────────────────────────────────┐
         ▼ (Segment 0 Begins Audio Playback)                                     ▼ (Segment 1 Begins Audio Playback)
- avatarEvents.emit("emotion", "Happy")                                 - avatarEvents.emit("emotion", "Angry")
- VRM Face -> Happy                                                     - VRM Face -> Shifts to Angry
- AnalyserNode -> LipSync RMS -> 'aa', 'ee'                             - AnalyserNode -> LipSync RMS -> 'ou', 'oh'
                                             │
                                             ▼ (All Audio Ends)
                              avatarEvents.emit("speech_end")
                                             │
                                             ▼
                                VRM Face -> Lerps to Neutral
```

### 6.1 Strict Emotion Presets & Canonical Mapping
The LLM is restricted to 6 core emotion tags in `./server/src/prompts/system_prompt_akari.py`:
- `[happy]`, `[sad]`, `[angry]`, `[surprised]`, `[relaxed]`, `[neutral]`.

Expressive variations emitted by third-party models are mapped defensively to the 6 core presets via `EMOTION_ALIASES`:
- `annoyed`, `pouting`, `furious`, `mad` $\to$ `Angry`
- `blush`, `flustered`, `teasing`, `smirk` $\to$ `Happy`
- `shocked`, `confused`, `amazed` $\to$ `Surprised`
- `unhappy`, `crying`, `sulky`, `depressed` $\to$ `Sad`
- `calm`, `sleepy`, `tired` $\to$ `Relaxed`

### 6.2 Dialogue Unit Splitter (`split_dialogue_units_with_emotions`)
In `./server/src/voice/emotion_feature.py`:
- Retains emotion markers during regex tokenization (`r"(\[[a-zA-Z_\-]+\])"`).
- Chunks sentences at punctuation boundaries (`[.!?\n]`) and caps dialogue units at 16 words.
- Each chunk preserves its contextual emotion: `(dialogue_text, active_emotion)`.

### 6.3 Parallel TTS & Client SpeechQueue
- The server generates audio for each dialogue unit via Fish Audio or GPT-SoVITS and dispatches `speech_segment` events with `audio` (base64 WAV Data URI), `text`, and `emotion`.
- `./client/src/audio/SpeechQueue.ts`:
  - `playNext()` triggers `avatarEvents.emit({ type: "emotion", emotion: segment.emotion })` the exact millisecond audio playback begins.
  - When the queue drains completely, `notifyAllEnd()` emits `speech_end`, prompting `EmotionController` to smoothly lerp the face back to `Neutral`.
- **Absolute Asterisk Ban**: Markdown asterisks `*` are stripped on both server (`strip_all_emotion_tags`) and client (`cleanSubtitleText` in `SubtitleOverlay.tsx`) to guarantee clean subtitles.

## 7. Multimodal Vision & Attachment Architecture

The multimodal vision subsystem accepts images from the browser UI and passes them to the AI companion.

### 7.1 Client-Side Preprocessing (`./client/src/utils/imageUtils.ts`)
- **Offscreen Canvas Downscaling**: Proportionally resizes large phone/camera images (10MB–20MB) to fit within a $1280 \times 1280$ bounding box.
- **JPEG Compression**: Re-encodes at `quality = 0.85`, compressing images to under 150 KB in under 50ms.
- **Glassmorphic Input Integration** (`./client/src/components/ChatInput.tsx`):
  - Camera action button (`.chat-btn-camera`) opening the native file picker.
  - Drag-and-drop with ambient purple glow (`.dragging`) on hover.
  - Clipboard paste listener (`onPaste`) intercepting screenshots.
  - Dismissible preview chip (`44x44px` thumbnail, filename, size) with one-click removal (`IconX`).

### 7.2 Hybrid Vision Routing (`./server/src/llm/provider.py`)
1. **Native Multimodal Models**:
   When `is_vision_supported()` returns True (Ministral 3, Mistral Large 3, Qwen 3 VL, OpenAI GPT-4o, Mistral Pixtral 12B, OpenRouter Free):
   - The base64 Data URI is passed directly into the model's native multimodal message payload (`image_url`).
2. **Text-Only Models (Background Vision Analyzer)**:
   When routing to text-only models (OpenAI GPT-OSS, Mistral 8B, Qwen 2.5 7B, Ling 3.0 Flash):
   - `./server/src/llm/vision.py` queries a dedicated vision model in the background.
   - Generates an objective, structured analysis covering subjects, environment, readable text/logos, and artistic style.
   - Injects the visual description directly into the prompt context (`[Image description:\n...] {user_prompt}`) without crashing the text-only model.

## 8. Conversation Memory Compaction

To prevent context drift and unbounded token consumption during extended sessions, `./server/src/llm/compactor.py` implements the **Summary Buffer Memory** pattern.

### 8.1 Gating Thresholds
- `COMPACTION_THRESHOLD_MESSAGES = 16` (~8 complete conversational turns).
- `COMPACTION_THRESHOLD_CHARS = 8000` (~2,000 tokens).
- Turns 1–7 bypass compaction with zero latency overhead.

### 8.2 Recency Preservation & Cumulative Memory
- `KEEP_RECENT_MESSAGES = 6` (~3 recent turns) are preserved verbatim, maintaining immediate pronoun references and recent tool outputs.
- Older turns are compiled into a structured dialogue transcript and summarized by the active LLM into an objective background memory block:
  ```
  [UserMessage("[Context from earlier conversation:\n<summary>\n(Background memory)]")]
  [AssistantMessage("[Understood, I remember everything we talked about.]")]
  ```
- **Fail-Safe Mechanism**: If summarization fails or times out, the compactor gracefully falls back to sliding-window truncation.

## 9. Full-Duplex WebSocket Protocol & Event Bus

Communication between the frontend and backend operates over a single WebSocket connection on `ws://127.0.0.1:8765`.

### 9.1 Binary Frame Specification

| Byte 0 Header | Type | Payload | Flow | Description |
|---|---|---|---|---|
| `0x01` | `AUDIO_CHUNK` | Binary audio bytes | Server $\to$ Client | Raw audio chunk for gapless streaming playback |
| `0x02` | `AUDIO_END` | Empty | Server $\to$ Client | Signals audio stream completion |
| `0x03` | `AUDIO_INTERRUPT` | Empty | Bi-directional | Immediately halts generation and playback |
| `0x10` | `VOICE_CHUNK` | Int16 PCM (16kHz) | Client $\to$ Server | Streamed microphone voice audio |
| `0x11` | `VOICE_END` | Empty | Client $\to$ Server | Recording stopped; triggers final ASR pass |

### 9.2 Typed JSON Event Protocol (`./client/src/networking/types.ts`)

#### Client to Server
```typescript

```
