## 1. Executive Summary & Persona Specification

### 1.1 Project Mission
The **Akari Watanabe assistant** is a low-latency, multimodal AI assistant application. It renders a 3D VRM anime avatar in a web interface powered by WebGL/Three.js, driven by an asynchronous Python backend. The system unifies speech recognition, streaming conversational intelligence, fine-grained emotional parsing, low-latency text-to-speech synthesis, and audio-reactive 60 FPS facial lip-syncing.

### 1.2 Character Persona & Prompt Engineering
- **Character Name**: Akari Watanabe (渡辺 星).
- **Archetype**: Tsundere Gyaru (inspired by *More Than a Married Couple, But Not Lovers*).
- **Core Dynamics**:
  - **Surface Persona**: Confident, outspoken, slightly demanding, and teasing. Proud of her fashion, appearance, and social status.
  - **Inner Persona**: Deeply affectionate, loyal, and easily flustered by genuine romantic gestures or direct compliments.
  - **Interaction Style**: Uses playful jabs and feigned annoyance ("I-it's not like I made breakfast for you or anything, idiot!") while actively caring for the user.
- **Strict Emotion Tag Rules**:
  The system prompt (`server/src/prompts/system_prompt_akari.py`) enforces strict emission of **only 6 emotion tags**:
  `[happy]`, `[sad]`, `[angry]`, `[surprised]`, `[relaxed]`, `[neutral]`.
  The LLM is strictly prohibited from emitting asterisks `*` or roleplay stage directions (e.g. `*looks away*` is forbidden; `[angry] Stop staring at me!` is mandated).

## 2. Complete Unabridged Code: `server/src/chat/loop.py`

```python
"""
Chat Loop
---------
Processes a single chat message from the browser UI.

Mirrors the same LLM → TTS → dispatch pipeline as voice/loop.py,
but receives text directly instead of listening on the server mic.
Supports immediate stream cancellation when user clicks Stop.
"""

from __future__ import annotations

import asyncio
import re
import string
import base64
import threading

from mistralai.client.models import (
    AssistantMessage,
    UserMessage,
)

from src.config import ENABLE_SUBTITLES
from src.bridge.dispatcher import dispatch
from src.bridge.events import (
    transcript,
    speech_start,
    speech_end,
    speech_segment,
    turn_end,
    thinking_start,
    thinking_end,
)
from src.llm.mistral_model import stream_chat
from src.tts.text_to_speech import convert_to_wav
from src.voice.emotion_feature import (
    EmotionFeatureManager,
    strip_all_emotion_tags,
    split_dialogue_units_with_emotions,
)
from src.prompts.system_prompt_akari import EXIT_PHRASES


def split_into_dialogue_units(text: str, max_words: int = 16) -> list[str]:
    sentences = re.split(r"(?<=[.!?\n])\s+", text.strip())
    sentences = [s.strip() for s in sentences if s.strip()]
    if not sentences:
        return [text.strip()] if text.strip() else []

    units: list[str] = []
    current_unit: list[str] = []
    current_word_count = 0

    for s in sentences:
        s_words = len(s.split())
        if current_unit and (current_word_count + s_words > max_words):
            units.append(" ".join(current_unit))
            current_unit = [s]
            current_word_count = s_words
        else:
            current_unit.append(s)
            current_word_count += s_words

    if current_unit:
        units.append(" ".join(current_unit))

    return units


# ─── Shared conversation history & active task tracking ──────────────────────

_history: list = []
_active_cancel_event: threading.Event | None = None
_active_chat_task: asyncio.Task | None = None
_suppress_cancel_speech_end = False


def set_active_chat_task(task: asyncio.Task | None):
    global _active_chat_task
    _active_chat_task = task


async def stop_chat_stream(emit_speech_end: bool = True):
    """Immediately halts the active LLM stream, TTS synthesis, and speech dispatch."""
    global _active_cancel_event, _active_chat_task, _suppress_cancel_speech_end
    print(f"[Chat] Stopping active stream (emit_speech_end={emit_speech_end})...")

    if not emit_speech_end:
        _suppress_cancel_speech_end = True

    if _active_cancel_event is not None:
        _active_cancel_event.set()

    if _active_chat_task is not None and not _active_chat_task.done():
        _active_chat_task.cancel()
        try:
            await _active_chat_task
        except (asyncio.CancelledError, Exception):
            pass
        _active_chat_task = None

    if emit_speech_end:
        await speech_end()

    _suppress_cancel_speech_end = False
    print("[Chat] Stream successfully stopped.")


async def process_chat_message(user_text: str):
    """
    End-to-end pipeline for a user chat message:
      1. Dispatch transcript event (so client can show what the user said)
      2. Stream LLM response
      3. Generate TTS audio per dialogue unit
      4. Dispatch speech_segment events to client
    """
    global _history, _active_cancel_event

    if not user_text.strip():
        return

    cancel_event = threading.Event()
    _active_cancel_event = cancel_event

    print(f"[Chat] You: {user_text}")
    await transcript(user_text)
    await thinking_start()

    # Check for exit phrases
    cleaned = user_text.strip().lower().strip(string.punctuation)
    if cleaned in EXIT_PHRASES:
        goodbye = "...fine, bye. Don't miss me too much."
        print(f"[Chat] Akari: {goodbye}")
        wav_bytes = await asyncio.to_thread(convert_to_wav, goodbye)
        b64_audio = base64.b64encode(wav_bytes).decode("ascii")
        data_uri = f"data:audio/wav;base64,{b64_audio}"
        await speech_start()
        await speech_segment(
            text=goodbye if ENABLE_SUBTITLES else "",
            audio=data_uri,
            is_last=True,
            segment_index=0,
            total_segments=1,
            emotion="Sad",
        )
        await turn_end()
        return

    full_reply: list[str] = []
    emotion_mgr = EmotionFeatureManager()

    loop = asyncio.get_running_loop()
    unit_queue: asyncio.Queue[tuple[str, str] | None] = asyncio.Queue()

    def stream_and_chunk():
        print("[Chat] Akari: ", end="", flush=True)
        buffer = ""
        current_sentence = ""

        try:
            for token in stream_chat(user_text, _history):
                if cancel_event.is_set():
                    print("\n[Chat] Stream cancelled by user stop request.")
                    return

                print(token, end="", flush=True)
                full_reply.append(token)
                buffer += token

                buffer = emotion_mgr.on_token(token, buffer, dispatch)
                current_emotion = emotion_mgr.detected_emotion or "Neutral"

                if "[" in buffer:
                    last_bracket = buffer.rfind("[")
                    if last_bracket > 0:
                        current_sentence += buffer[:last_bracket]
                        buffer = buffer[last_bracket:]
                else:
                    if buffer:
                        current_sentence += buffer
                        buffer = ""

                # Check for dialogue unit boundary (. ! ? followed by space, or max 16 words)
                words = current_sentence.split()
                has_sentence_end = bool(re.search(r"[.!?\n]\s*$", current_sentence))
                if (has_sentence_end and len(words) >= 3) or len(words) >= 16:
                    clean = strip_all_emotion_tags(current_sentence).strip()
                    if clean:
                        loop.call_soon_threadsafe(unit_queue.put_nowait, (clean, current_emotion))
                    current_sentence = ""

            if buffer:
                current_sentence += buffer
            clean = strip_all_emotion_tags(current_sentence).strip()
            if clean:
                current_emotion = emotion_mgr.detected_emotion or "Neutral"
                loop.call_soon_threadsafe(unit_queue.put_nowait, (clean, current_emotion))

        except Exception as e:
            if not cancel_event.is_set():
                print("[Chat] LLM stream error:", e)
        finally:
            print()
            loop.call_soon_threadsafe(unit_queue.put_nowait, None)

    llm_task = asyncio.create_task(asyncio.to_thread(stream_and_chunk))

    segment_index = 0
    speech_started = False
    pending: tuple[str, str, str, int] | None = None

    try:
        while True:
            if cancel_event.is_set():
                break

            try:
                unit = await asyncio.wait_for(unit_queue.get(), timeout=0.1)
            except asyncio.TimeoutError:
                if cancel_event.is_set():
                    break
                if llm_task.done() and unit_queue.empty():
                    break
                continue

            if cancel_event.is_set():
                break

            # If we had a pending unit, we now know whether it was the last or not:
            if pending is not None:
                p_text, p_emotion, p_audio, p_idx = pending
                is_last_unit = (unit is None)
                if not speech_started:
                    await speech_start()
                    speech_started = True

                await speech_segment(
                    text=p_text if ENABLE_SUBTITLES else "",
                    audio=p_audio,
                    is_last=is_last_unit,
                    segment_index=p_idx,
                    total_segments=-1,
                    emotion=p_emotion if emotion_mgr.mode == "synced" else None,
                )
                pending = None

            if unit is None:
                break

            u_text, u_emotion = unit

            try:
                wav_bytes = await asyncio.to_thread(convert_to_wav, u_text)
                if cancel_event.is_set():
                    break

                b64_audio = base64.b64encode(wav_bytes).decode("ascii")
                data_uri = f"data:audio/wav;base64,{b64_audio}"
                pending = (u_text, u_emotion, data_uri, segment_index)
                segment_index += 1
            except Exception as e:
                if not cancel_event.is_set():
                    print(f"[Chat] TTS error for '{u_text}':", e)

        # Flush any remaining pending unit as is_last=True
        if pending is not None and not cancel_event.is_set():
            p_text, p_emotion, p_audio, p_idx = pending
            if not speech_started:
                await speech_start()
                speech_started = True

            await speech_segment(
                text=p_text if ENABLE_SUBTITLES else "",
                audio=p_audio,
                is_last=True,
                segment_index=p_idx,
                total_segments=-1,
                emotion=p_emotion if emotion_mgr.mode == "synced" else None,
            )

        if not cancel_event.is_set():
            await llm_task
            await turn_end()
            emotion_mgr.on_speech_concluded(dispatch)

            raw_reply = "".join(full_reply)
            clean_reply = strip_all_emotion_tags(raw_reply).strip()
            if clean_reply:
                _history.append(UserMessage(content=user_text))
                _history.append(AssistantMessage(content=clean_reply))
        else:
            if not llm_task.done():
                llm_task.cancel()
            await speech_end()
            emotion_mgr.on_speech_concluded(dispatch)

    except asyncio.CancelledError:
        cancel_event.set()
        if not llm_task.done():
            llm_task.cancel()
        if not _suppress_cancel_speech_end:
            await speech_end()
            emotion_mgr.on_speech_concluded(dispatch)
        raise
    finally:
        _active_cancel_event = None
```

## 4. Chat Pipeline Deep Dive (`chat/loop.py`)

### 4.1 Token Streaming & Unit Chunking
Instead of waiting for the full LLM reply to finish before triggering TTS (which incurs unacceptable 3–6 second delays), `chat/loop.py` uses an asynchronous **Dialogue Unit Pipeline**:
1. **Parallel Worker Thread (`stream_and_chunk`)**:
   Calls `stream_chat(user_text, _history)` on a background thread.
2. **Buffer Splitting Criteria**:
   Tokens accumulate in `current_sentence`. A unit is emitted when:
   - A punctuation boundary (`. ! ? \n`) is encountered with $\ge 3$ words, OR
   - The word count reaches the maximum threshold of $16$ words.
3. **Punctuation and Tag Guard**:
   If an emotion tag bracket `[` is currently open in the buffer, splitting is suppressed until the closing `]` is received, preventing cut-off tags like `[hap` and `py]`.
4. **Inter-Thread Queue (`unit_queue`)**:
   Tokens are posted to an `asyncio.Queue` via `loop.call_soon_threadsafe(unit_queue.put_nowait, (clean_text, emotion))`.

### 4.2 Lookahead `is_last` Signaling (`pending` tuple)
To inform the client when a turn concludes without relying on a disconnected end message:
- The consumer loop buffers the current synthesized WAV segment into a `pending = (text, emotion, audio_uri, index)` tuple.
- Only when the *next* unit is dequeued from `unit_queue` can the system know whether `pending` was the terminal unit:
  - If `next_unit is None`: `is_last = True`.
  - If `next_unit` exists: `is_last = False`.
- This ensures the browser's `SpeechQueue` knows precisely when to fire final turn wrap-ups and trigger state transitions.

### 4.3 Instant Stream Cancellation
When the user clicks the **Stop** button in the chat interface:
1. Client sends `{ "type": "interrupt" }` or binary packet `0x03`.
2. `stop_chat_stream()` in `chat/loop.py` is invoked:
   - Sets `cancel_event.set()` (a `threading.Event`), immediately breaking the LLM token iteration.
   - Cancels `_active_chat_task` (`asyncio.Task.cancel()`).
   - Dispatches `speech_end()` to reset client speaking animations.
   - Resets facial blendshapes via `emotion_mgr.on_speech_concluded(dispatch)`.

## 6. Whisper Dual-Model ASR & Mutual Exclusion Subsystem

To avoid Out-Of-Memory (OOM) errors and CPU saturation on systems running local inference:
1. **`chat_whisper.py`** loads OpenAI Whisper **`small.en`**:
   - Optimized for fast, lightweight interim word transcription streamed from browser audio chunks.
   - Function `unload_stream_model()` unloads model weights and calls `gc.collect()` and `torch.cuda.empty_cache()`.
2. **`server_asr.py`** loads OpenAI Whisper **`medium`**:
   - Optimized for high-accuracy speech transcription from server hardware mics.
   - Function `unload_asr_model()` clears model weights from memory.
3. **Mutual Exclusion in `websocket_server.py`**:
   - When client requests `set_mode` with `chat_input_enabled=True`:
     `stop_voice_loop()` $\to$ `unload_asr_model()`.
   - When client requests `set_mode` with `chat_input_enabled=False`:
     `unload_stream_model()` $\to$ `start_voice_loop()`.
   - Result: Only **one** Whisper model exists in memory at any time.

## 7. Emotion Extraction & VRM Expression Synchronization

### 7.1 Architecture of `EmotionFeatureManager` (`src/voice/emotion_feature.py`)
- **Token Buffering**:
  Tokens arrive one by one (`"["`, `"hap"`, `"py]"`). `EmotionFeatureManager.on_token()` buffers partial sequences starting with `[` and only processes them when `]` is encountered.
- **Regex Tag Mapping**:
  Supported emotion tags map directly to standard VRM blendshapes:
  - `[happy]` $\to$ `Joy` / `Happy`
  - `[angry]` $\to$ `Angry`
  - `[sad]` $\to$ `Sorrow` / `Sad`
  - `[surprised]` $\to$ `Surprised`
  - `[relaxed]` $\to$ `Relaxed`
  - `[neutral]` $\to$ `Neutral`
- **TTS Text Purification**:
  `strip_all_emotion_tags()` strips all bracketed expressions before passing text to the TTS engine so Akari never vocalizes words like *"bracket happy bracket"*.
- **Post-Speech Decay**:
  `on_speech_concluded()` sends an emotion reset event to smoothly return the avatar's face to `Neutral` over 400ms.

## 8. Audio Synthesis, Web Audio Queue & Audio-Reactive LipSync

### 8.1 TTS Generation
- Engines: **Fish Audio API** (primary cloud endpoint) or **GPT-SoVITS** (local high-fidelity voice cloning).
- Output: 24kHz / 44.1kHz 16-bit PCM WAV. Base64 encoded as `data:audio/wav;base64,...`.

### 8.2 Gapless Web Audio Scheduling (`AudioPlayer.ts`)
Standard HTML `<audio>` elements suffer from 50–150ms gaps between segments. The client utilizes Web Audio API:
$$\text{startTime} = \max(\text{audioCtx.currentTime}, \text{scheduledEndTime})$$
$$\text{scheduledEndTime} = \text{startTime} + \text{buffer.duration}$$
This guarantees mathematical phase-aligned gapless playback across segmented dialogue chunks.

### 8.3 Speech Queue & Turn Watchdog (`SpeechQueue.ts`)
- **Extended Watchdog**: Fallback timer increased from 20s to **60s** to prevent premature state cancellation during prolonged local LLM CPU inference.
- **Active State (`isPlaying`)**:
  - Sets `isPlaying = true` immediately upon clicking **Send** in `ChatInput.tsx`.
  - Persists continuously through thinking, streaming, synthesis, and audio queue drainage.
  - Clears `isPlaying = false` only after the terminal segment's `onended` callback finishes.

### 8.4 RMS Live Lip-Sync (`LipSyncController.ts`)
- Avoids rigid pre-baked viseme JSON curves.
- Binds a Web Audio `AnalyserNode` with `fftSize = 512`.
- Computes Root-Mean-Square volume on every `requestAnimationFrame`:
  $$\text{RMS} = \sqrt{\frac{1}{N} \sum_{i=0}^{N-1} x[i]^2}$$
- Dynamically scales mouth opening morph targets (`aa`, `ih`, `ou`, `ee`, `oh`) with smooth exponential attack and decay filters.

## 9. WebSocket Protocol & Event Bus Specification

### 9.1 Connection Endpoint
`ws://127.0.0.1:8765`

### 9.2 Binary Frame Specification
| Packet ID | Hex | Name | Payload | Direction |
| :--- | :--- | :--- | :--- | :--- |
| `1` | `0x01` | `AUDIO_CHUNK` | Raw audio bytes | Server $\to$ Client |
| `2` | `0x02` | `AUDIO_END` | Empty | Server $\to$ Client |
| `3` | `0x03` | `AUDIO_INTERRUPT` | Empty | Bidirectional |
| `16` | `0x10` | `VOICE_CHUNK` | 16-bit 16kHz PCM audio | Client $\to$ Server |
| `17` | `0x11` | `VOICE_END` | Empty | Client $\to$ Server |

### 9.3 JSON Frame Specification
- **`config`** (Server $\to$ Client):
  ```json
  { "type": "config", "chat_input_enabled": true }
  ```
- **`set_mode`** (Client $\to$ Server):
  ```json
  { "type": "set_mode", "chat_input_enabled": true, "mode": "chat", "screen": "chat" }
  ```
- **`chat_message`** (Client $\to$ Server):
  ```json
  { "type": "chat_message", "text": "Hello Akari!" }
  ```
- **`transcription`** (Server $\to$ Client, Interim Live Words):
  ```json
  { "type": "transcription", "text": "Hello", "is_final": false }
  ```
- **`transcript`** (Server $\to$ Client, Confirmed Turn Text):
  ```json
  { "type": "transcript", "text": "Hello Akari!" }
  ```
- **`speech_segment`** (Server $\to$ Client, Audio Unit):
  ```json
  {
    "type": "speech_segment",
    "text": "What do you want, idiot?",
    "audio": "data:audio/wav;base64,...",
    "is_last": false,
    "segment_index": 0,
    "total_segments": -1,
    "emotion": "Angry"
  }
  ```
- **`emotion`** (Server $\to$ Client, Avatar Morph Event):
  ```json
  { "type": "emotion", "emotion": "Angry" }
  ```
- **`interrupt`** (Client $\to$ Server):
  ```json
  { "type": "interrupt" }
  ```

## 12. Multi-Provider LLM Integration (`./server/src/llm/`)

### 12.1 Supported Providers
1. **Mistral AI (`./server/src/llm/mistral_model.py`)**:
   - Official Mistral Python SDK (`mistralai`).
   - Models: `ministral-8b-latest` (default), `pixtral-12b-2409`, `mistral-small-latest`, `open-mistral-7b`.
2. **OpenAI (`./server/src/llm/openai_model.py`)**:
   - Official OpenAI client with dynamic runtime API key management (`./spec/openai_and_api_keys.md`).
   - Models: `gpt-4o-mini` (default / recommended), `gpt-4o`, `gpt-4-turbo`, `gpt-3.5-turbo`.
   - Supports native multimodal image vision and autonomous multi-round tool calling.
3. **Free.ai (`./server/src/llm/freeai_model.py`)**:
   - Universal endpoint (`https://api.free.ai/v1/chat/`) with SSE token streaming via `httpx.stream`.
   - Models: `qwen7b`, `qwen3-8b`.
   - Comprehensive technical learnings documented in `./spec/freeai_and_settings_learnings.md`.
4. **OpenRouter (`./server/src/llm/openrouter_model.py`)**:
   - Free multimodal and reasoning models via `openrouter/free`, `ling-3.0-flash`, `liquid-lfm`.
   - Documented in `./spec/openrouter_integration.md`.

### 12.2 Provider Abstraction & Management (`./server/src/llm/provider.py`)
- Central dispatcher exposing `stream_chat(prompt, history)` and `classify_emotion(text)`.
- Handles history normalization between Mistral objects (`UserMessage`, `AssistantMessage`) and standard OpenAI dicts (`{"role": "user"|"assistant", "content": ...}`).
- **Dynamic API Key Synchronization**: Clients can save and update API keys directly via Settings UI, persisted locally in browser `localStorage` and synchronized dynamically to backend memory via WebSocket `{ type: "set_api_key" }`.
- **Model Execution Guarantee**: `set_active_provider(provider_id, model_id)` directly applies `model_id.strip()` without falling back silently to default models. Invalid models trigger transparent upstream API error feedback.
- Synchronized with client via WebSocket `set_llm_provider`, `chat_message` metadata payloads, and `config` broadcasts.
- Integrated into the dedicated Settings screen in `./client/src/components/screens/SettingsScreen.tsx`.

## 13. Multimodal Vision & Attachment Architecture

### 13.1 Overview & Design Principles
Introduced in branch `feat/image-support` (specified in `./spec/image_support_and_multimodal_vision.md`), this subsystem enables visual perception for Akari Watanabe. Users can transmit images alongside chat messages via:
1. Pinned camera file picker button (`.chat-btn-camera`)
2. Drag-and-drop onto the glassmorphic input container (`.chat-input-bar`)
3. Clipboard paste listener (`Ctrl+V` / `Cmd+V`)

To preserve the immersion and clean aesthetic of the 3D WebGL avatar viewport, sent images are dismissed upon dispatch and are **not** rendered as floating overlay cards over the 3D scene.

### 13.2 Client-Side Preprocessing (`./client/src/utils/imageUtils.ts`)
- **Offscreen Canvas Downscaling**: High-resolution smartphone/camera photos (often 10–20MB) are decoded and proportionally constrained to a maximum bounding box of $1280 \times 1280$ pixels using an offscreen canvas.
- **Re-compression**: Encoded as JPEG at $0.85$ quality, routinely shrinking raw uploads to $<150\text{ KB}$ within $<50\text{ ms}$, preventing WebSocket buffer saturation.
- **Preview Chip**: Displays a dismissible thumbnail (`44x44px`), file name, and file size above the textarea before dispatch.

### 13.3 Extensible Attachment Protocol & Server Validation
- **Schema (`./client/src/networking/types.ts`)**:
  Messages support an extensible `attachments: ChatAttachment[]` array containing `id`, `type`, `mime`, `data`, `name`, and `size`. For backward compatibility, single `image: string` base64 URIs are also accepted.
- **Server Guardrails (`./server/src/bridge/websocket_server.py`)**:
  - Enforces a 7 MB payload ceiling.
  - Whitelists image MIME types (`image/jpeg`, `image/png`, `image/webp`, `image/gif`).
  - Validates Data URI syntax before passing to `chat/loop.py`.

### 13.4 Hybrid Inference Pipeline (`./server/src/llm/provider.py` & `./server/src/llm/vision.py`)
- **Native Vision Execution**:
  When active provider/model supports vision (e.g. `pixtral-12b-2409` on Mistral or `openrouter/free` on OpenRouter), base64 image data is passed directly via provider-specific multimodal message structures (`UserMessage(content=[{"type": "image_url", ...}])`).
- **Comprehensive Background Visual Extraction**:
  When text-only models are selected (e.g. `ministral-8b-latest`, `qwen7b`, `deepseek-r1`), `./server/src/llm/vision.py` queries `pixtral-12b-2409` or `openrouter/free` in the background with a 1000-token budget. It extracts a comprehensive, purely objective visual description (subjects, poses, clothing, background, verbatim OCR text, style, fine details) without anime or persona bias.
- **Direct Visual Context Injection**:
  Extracted visual features are provided directly to the model without excessive meta-prompts:
  ```text
  [Image description:
  <verbose_visual_analysis>]

  <user_prompt>
  ```
- **Persona Guidance (`./server/src/prompts/system_prompt_akari.py`)**:
  A single concise rule guides the AI to react naturally in character to images rather than dryly reciting them like a robot, keeping the prompt free from excess instructions.

### 13.5 OpenAI Native Multimodal Vision Support
- **Direct Image Transmission**:
  OpenAI natively supports direct image inputs (`gpt-4o`, `gpt-4o-mini`, `gpt-4-turbo`). When OpenAI is the active provider, the backend skips the secondary vision feature extraction pipeline entirely (`analyze_image`) and feeds the image Data URI directly into `stream_chat(prompt, history, image=pass_image)`.
- **OpenAI Multimodal Formatting (`./server/src/llm/openai_model.py`)**:
  Builds standard OpenAI content arrays:
  ```python
  {"role": "user", "content": [
      {"type": "text", "text": prompt},
      {"type": "image_url", "image_url": {"url": image}}
  ]}
  ```
- **Context Retention in Tool Calling**:
  The image message remains present in the conversation context during multi-round autonomous tool calling loops.

## 14. Clean URL Architecture & Client Storage Schema (2026-09-29)

### 14.1 Query Parameter Simplification
- **No `provider` in URL**: `provider` is omitted from browser query parameters to keep links human-readable and clean. Provider is dynamically inferred from `model` (e.g. `gpt-*` -> `openai`, `openrouter/*` -> `openrouter`, `mistral*` -> `mistral`, `qwen*` -> `freeai`) or retrieved from `localStorage.getItem("akari_llm_provider")`.
- **Only `model` in URL**: The URL query string only includes `screen`, `character`, and `model` (e.g. `/?screen=settings&character=akari&model=gpt-4o-mini`).
- **Tool Calling in LocalStorage**: The tool calling toggle state is omitted from the URL and persisted exclusively in `localStorage.getItem("akari_tool_calling_enabled")` (defaulting to `true`).
- **Automatic Canonicalization**: On initial application mount, legacy URL query parameters (`&provider=...`, `&tools=...`) are stripped without triggering full page reloads via `window.history.replaceState`.
