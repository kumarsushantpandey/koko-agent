## 3. Tool Calling Discovery & Pre-Decline Rule

### 3.1 The Problem
When queried about her tools or capabilities (*"what tools do you have?"* or *"can you check system status?"*), the assistant frequently:
1. Answered from memory or declined without executing tools.
2. Failed to invoke `get_available_tools` because the prompt selection guide lacked discovery instructions.
3. Threw an unrecognized tool error when models called `get_tool_list`.

### 3.2 The Solution
1. **Registered Alias**:
   In `server/src/tools/builtins.py`, registered `get_tool_list` pointing to `get_available_tools`.
2. **Resilient Registry Lookup**:
   In `server/src/tools/registry.py`:
   ```python
   def get_tool(self, name: str) -> Tool | None:
       tool = self._tools.get(name)
       if tool is not None:
           return tool
       if name in ("get_tool_list", "tool_list", "tools_list", "list_tools", "get_tools"):
           return self._tools.get("get_available_tools") or self._tools.get("get_tool_list")
       if name in ("get_available_tools", "available_tools"):
           return self._tools.get("get_tool_list") or self._tools.get("get_available_tools")
       return None
   ```
3. **Mandatory System Prompt Rule**:
   In `server/src/prompts/system_prompt_akari.py`:
   - Enforced that **before declining any request or saying she cannot do something**, Akari MUST execute `get_available_tools` / `get_tool_list` to check her registered catalog.
   - Directed tool discovery queries (*"get tool list"*, *"what tools do you have"*) directly to the discovery tool.

## 4. Scaling Tool Calling Window to 20 Rounds

Complex multi-step workflows (such as discovering available tools $\to$ inspecting web content $\to$ performing calculations $\to$ responding) require multi-round chaining.

### 4.1 Changes Applied
1. **Configuration**:
   - `server/src/config.py`: `MAX_TOOL_CALL_ROUNDS = int(os.getenv("MAX_TOOL_CALL_ROUNDS", "20"))`
   - `server/.env` & `server/.env.example`: Added `MAX_TOOL_CALL_ROUNDS=20`.
2. **Streaming Callbacks**:
   - `provider.py`, `bedrock_model.py`, `openai_model.py`, `openrouter_model.py`, `mistral_model.py`, `freeai_model.py`, and `chat/loop.py` updated to use `max_tool_rounds = MAX_TOOL_CALL_ROUNDS` (20).
3. **WebSocket Bridge**:
   - `websocket_server.py`: Clamping relaxed from `min(10, ...)` to `min(20, ...)`.
4. **Client Networking**:
   - `AvatarSocket.ts`: Updated default `maxCalls` to `20` when initializing or toggling tool calling.
